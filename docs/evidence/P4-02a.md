## Scope and test results

The new main-only owner is imported by its unit tests only. It reserves one active
attempt before callbacks/reflection, generates independent state/nonce/PKCE,
validates and consumes the exact loopback callback, binds initial/returning client
IDs and selected identity, and uses returned scopes to distinguish identity from
inference permission. Credential preparation/atomic installation is a trusted fake
contract. Failed replacement preserves the previous authorization; successful
replacement changes its incarnation. Cancellation, timeout, invalidation and
terminal disposal block late activation/installation before the commit claim.

Meaningful test-first evidence:

- Initial typed no-op contract: focused suite **26 failed**, including a missing
  launch and incorrect disposed result; no missing-module/compile failure used as
  the red result. Implemented the transaction and all 26 passed.
- Expanded negative/race suite: **152 passed**, initially 96.03% branches.
- Added an ID-only/no-access-or-refresh case: **1 failed / 152 skipped** because
  the prior contract rejected it. Added explicit nullable normalized credentials
  while keeping inference disabled; the regression now passes.
- Final focused suite: **164 cases**. Cases include duplicate/replayed/wrong
  callbacks, canonical URI and bounds, selected registration/subject, malformed
  grants and verified claims, access without refresh, missing inference scopes,
  hook errors, record/reflection/abort reentry, expiration, delayed exchanges,
  late staging, failed protected commit, renewal and terminal disposal.

Only ephemeral synthetic credential markers are generated in memory. Assertions
use fixed outcomes, metadata/booleans and side-effect counts. No real JWT, OAuth
account, token, screenshot or private user data is used or saved.

inform this independent contract, not a claim that an actual account works.

The application and lockfile are unchanged and the project remains UNLICENSED.

Direct review covers fixed destinations; exact redirect/state/client/nonce/account
binding; no inference from callback/requested scopes; safe failure vocabulary;
private token handling; prompt public cancellation; stale generation checks;
protected-commit ordering; grant renewal/invalidation; no ambient work; no new
renderer authority or silent account/provider/billing fallback. Fake verification
is explicitly not cryptographic validation, and fake staging is not Windows
protected storage or durable atomicity. Async final-write adapters cannot be
attached under this contract without an appropriate conditional commit design.
