## Scope and verification

P2-02 streams through the P2-01 adapter with main-owned lifecycle and the necessary
P2-03 restricted IPC. The user sees a fixed mock-provider display, partial text,
Stop/Retry/Clear and safe messages for every provider error code. P2-04 fixture
scenarios offline/auth expiry/rate limit/unsupported vision/cancellation are exposed
as explicit local simulations. Versioned shell settings already exist in P1-04.

## Direct security, privacy and licensing review

Reviewed main session/IPC, preload bridge, renderer effect/reducer and lifecycle
integration. Sender/frame/URL/argument checks precede provider operations. Start
rejects extra keys (including images and endpoints), bounds prompt/run/scenario,
allows one active request and rejects replay. Pulls are serialized and output is
bounded. Generation identity, abort and iterator cleanup prevent stale data after
Stop, Clear, reload and close. Only fixed error codes cross IPC; raw exceptions,
prompts and replies are not logged. Responses are rendered as plain escaped text.
No external services, capture, account, new disk write or provider fallback added.

Prompt text now enters transient main memory; README and privacy notice describe
this. History remains off; OS clipboard behavior remains disclosed. No dependency,
asset or copied third-party code was introduced. Existing licensing disposition is
unchanged; source license/binary distribution clearance is not inferred. See
[ADR 0013](../adr/0013-main-chat-stream.md) for risks and alternatives.
