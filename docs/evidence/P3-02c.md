## Acceptance evidence

The new `--selection-self-test` runs in three fresh processes in the required
Windows native step, alongside the original triple probe and argument rejection.
It tests:

- Two live windows with identical title/PID/thread metadata and distinct pixel
  landmarks: selecting either must capture that fixture's own colors.
- Selection alone creates zero frame pools/sessions/frames; consumed, wrong or
  zero generation requests start no capture.
- Blocked/empty/oversized metadata before selection; blocked or renamed title,
  hidden/minimized state or closure before acquisition: zero starts/accepted
  frames, no alternate target.
- Same-process, same-title replacement with a distinct lifetime/color palette:
  old selection denied immediately; fresh selection succeeds. No forced HWND
  reuse claim and no wait for a Closed event to authorize rejection.
- A controlled title change during capture waiting: one session starts, any
  candidate is discarded, native close counters balance, replay starts nothing.

The existing 19 native transport cases and 48 repeated Electron tests remain
required. Native C++ and batch files receive compiler/direct review, outside the
TypeScript coverage metric. Linux has no Windows SDK/MSVC, so native compilation,
native test-first red and runtime tests are **not run locally**. Windows CI
results, exact PR head, imports and final review are recorded in issue #71/PR
before handoff. No physical Windows or real-provider tests are performed.

Local final verification: `npm run check` passed all 780 units, coverage, static

Windows-only native and Electron results remain separate CI evidence.

## Security, permissions and licensing review

Fixture selection accepts only the typed owned-window object, never an HWND or
title from input. Lifetime revokes before destruction and on WM_NCDESTROY, with
shared callback/identity storage retained as long as needed. Metadata reads are
bounded and cleared; PID/thread/title equality is explicitly not foreign-window
identity. Acquisition consumes its selection and rechecks metadata after the
message-pumping frame wait. Expected landmarks are supplied independently by
the test; matching a title alone cannot pass the two-window case. All tested
pre-start denials must have zero session starts and balanced native resources.

No source enumeration, thumbnail gallery, foreground hook, external target,
shell, elevation, new app permission, renderer IPC, file/image output, network
or provider is added. Diagnostics contain no titles, handles or pixel bytes.
No npm, lockfile, inventory or link-library change. Native source and fixture
colors are independently authored; no SDK/sample/art source was copied. Exact
MSVC 14.51.36231 and SDK 10.0.26100.0 pins remain. Native redistribution remains
separately uncleared under ADR 0018; there is no binary upload/release approval.

## Gate and next issue

This is a bounded native selection/metadata experiment, not an end-user selector
or proof that arbitrary external targets can be bound safely. OS picker identity
mapping, foreign observation-to-binding races, foreground/focus transitions,
real exclusions/consent, helper parent-death containment, physical DPI/HDR and
protected targets remain open. G1 physical evidence, G2 promotion, G3 and OD-02
are unchanged. Final maintainer privacy review is required.

Next smallest task: resolve the external identity/selection mechanism using the
recorded API limitations before implementing a real target adapter. Conversion
and real consent/exclusion/transmission integration follow that decision.
