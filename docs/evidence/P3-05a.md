## Scope and test mapping

`src/core/screen-authorization.ts` validates a complete primitive snapshot and
independently checks request lifecycle, intent, hard opt-outs, revisioned consent,
provider/account binding, authorization, vision, target identity/allowance and
OS permission. Output is only a fixed decision/reason. The predicate has no runtime
caller, side effect, timer, cache, persistence or prompt/image/credential input.

`tests/unit/screen-authorization.test.ts` covers each deny reason, all 2,048 boolean
failure combinations, provider/account/target changes, re-evaluation after revocation,
Include versus independent denials, every missing/wrong-type/accessor field, unknown
symbol/string fields, reflection failures and identifier/version boundaries.
The first test run failed because the module did not exist; implementation then
passed the 25 focused tests and strict typecheck.

T-CAP-001/003/010 map to no screen intent/no submission; T-CAP-004/005 to opt-out
priority and Include not bypassing gates; T-CAP-006/008 to target/permission denial
and changed target; T-CAP-013 to cancellation/consumed/stale request; T-CAP-014 to
vision capability. Malformed-policy tests support T-IPC-001's design, but are not
IPC integration tests. No actual capture/transmission calls occur in these tests.

Local `npm run check` passed 657 unit tests, formatting, lint, strict types, the
unchanged intent evaluation, builds and the 184-package license inventory.
`npm audit --audit-level=high` found zero vulnerabilities. The new authorization
module has 100% line, statement, branch and function coverage. Aggregate coverage
is 100% lines, 99.81% statements, 99.13% branches and 99.05% functions. No dependency
or threshold changed. Final native CI and review results are recorded in issue #40
and its PR against the exact candidate commit.

## Security, licensing and limits

Direct review checks every data path: only bounded synthetic/main-owned opaque
handles and booleans/numeric revision enter, and fixed literals leave. No logging,
filesystem, network, Electron API, renderer IPC or third-party code/assets added.
The trust/provenance of inputs, replay prevention, stage transitions and captured-byte
binding cannot be established by a stateless predicate. ADR 0015 explicitly requires
fresh main-owned revalidation and atomic one-shot orchestration before runtime use.
No source/distribution license or capture-platform decision is made by this work.

Manual Windows/provider tests not performed; no new checklist requested. Local native
Electron E2E not run because this environment has no display/Xvfb; Windows CI owns
the native regression. Its success is not physical display/permission evidence.

G1 and G2 promotion remain open for existing physical evidence. G3 remains open
for live consent/target/capture/privacy validation and the unchanged P3-04 recall
shortfall (86.7% versus 90%) and evaluation limits. P3-05 is only partially implemented.
Next smallest issue is P3-01 consent/onboarding controls with mocked, disabled
capture, then resolve OD-02 before actual target/capture integration. No P4 account
authorization or nostalgic-art redesign is included in this contract task.
