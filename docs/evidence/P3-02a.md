# P3-02a — Pure target lifecycle

12 October 2026. Issue #46. Exploratory P3 slice under plan section 4.

## Scope

`src/core/capture-target.ts` retains one opaque target and at most one pending
validation ticket. Each invocation starts empty with a new generation. Confirmed
identity binds once; submission binds a request once. Completion must present the
same frozen ticket object, matching target, strict identity confirmation and strict
allowed status. A matching completion consumes the ticket even when validation
fails. Copies, other owners' tickets, stale generations and repeated completion
cannot resolve a target. Cancellation and target/session/display/helper changes
clear pending work. Companion focus alone preserves it. Retry needs a new
invocation and fresh target validation.

No production import, OS API, capture hook, renderer/preload change, image bytes,
network, storage, dependency or permission is added. IDs must be bounded opaque
identifiers, not window titles. Future main/native adapters must supply trustworthy
identity and exclusion facts. This state machine cannot detect OS races, prove
freshness from booleans, or authorize capture/transmission. Its ticket is local
object identity, not a serialized IPC capability or a reusable capture permit.
The caller must revalidate native binding, consent and policy at each side effect.

## Direct security and licensing review

Inspected all new data paths: only bounded opaque IDs and counters are retained;
no prompts, titles, credentials or pixels are accepted or logged. Private state
and frozen tickets prevent external mutation; every invalidating lifecycle event
discards target/request references. Unknown or false identity/allowed values deny
resolution. A resolved value is not connected to authorization or capture code.
No copied source, asset, package or license change. Native helper build and
redistribution review remains a separate prerequisite.
