## Scope and test-first work

Two unwired main-only modules supply fixed-destination native public HTTPS and a
cached identity verifier. A small extraction reuses the existing token/context
grammar before egress; existing signature/claim/key rules remain unchanged.
No app entry/preload/renderer, IPC, provider, storage, capture, workflow,
dependency/lock/inventory or UI change. No actual OpenAI endpoint is called.

- Typed no-op verifier: **3 failed / 3 passed**. Real independent RSA validation,
  cache reuse and rotation failed behaviorally; not a compile/missing-module red.
- Minimum implementation: all 6 new cases plus **149 existing verifier cases**
  passed; strict types passed after the parser extraction.
- Native cancellation hardening: **1 failed / 57 passed**. A late response
  delivered after cancellation was not destroyed; the explicit late-response
  guard fixes it. Transport suite then passed all 58 cases.
- Expanded tests cover fixed URL/TLS/header policy, content type/encoding/length,
  bounded UTF-8 streaming, request/body errors, deadlines and cleanup; independent
  signatures, own metadata fields/destination substitution, raw response/key
  denials, cache/no-store/age/rotation/cooldown, reflective reentry, delayed native
  crypto, cancellation/invalidation/disposal/clock changes and transaction
  composition. Two test-fixture mistakes (tuple parameter binding and a readonly
  polluted-prototype fixture) were corrected; neither was an implementation
  failure or a relaxed assertion.

Native transport uses mocked `https.get` and actual Node event/byte streams.
Those tests verify requested TLS/hostname/agent/HTTP constraints and stream
cleanup, **not a real TLS handshake or live issuer provenance**. The existing
maintained verifier performs real RS256 math against ephemeral synthetic keys;
OpenSSL/Node signs fixtures independently. Private keys/JWTs are never written
or snapshotted; test assertions use safe identity facts, statuses and counts.
Fake endpoints are trusted test capabilities, not configurable production URLs.

Composition tests use the real cached verifier plus fake browser/exchange/store.
Valid signatures reach fake credential preparation with inference disabled;
wrong signature/nonce or substituted discovery URL cannot reach preparation.
No actual user/account/service, protected store, refresh/logout, inference or
capture is exercised by these composition tests.

## Security, licensing and limits

Direct review follows all token/context/public-key paths. Tokens never enter
metadata URLs, headers or bodies; the default reader has only two exact public
destinations, normal verified TLS with a forced minimum version, fixed headers,
no redirects/cookies/credentials and bounded streams/time. No logging, file
operation, browser session, renderer authority or upstream implementation reuse.
No dependency or source-license change: 185 reviewed packages, project UNLICENSED.

Provisional exact endpoint/RS256/key-shape/size/time/cache limits are local policy.
Actual issuer metadata and account compatibility are not proved. The trusted
transport injection can supply synthetic keys in tests; never expose it to an
untrusted renderer or treat a fake's success as real OpenAI provenance. Real
source/TLS/metadata validation remains required before production account use.

The memory cache obeys positive max-age/Age with a five-minute cap, no-store and
no-cache; one permitted refresh pair per call and a 30-second global cooldown
bound repeated unknown IDs. Failures retire old authority; known-key bad
signatures do not retry. Very short/no server cache permission can fail closed
during cooldown. No background request, disk cache or expired-key fallback.
Native crypto can settle late; no forced memory-erasure claim. Unchanged intent
precision/recall and G1–G4/OD-02 blockers remain explicit; production capture off.

Next smallest: durable installation/issued-registration retention and retry hints,
then browser/listener/code exchange, rotating refresh/logout and production
integration. OD-04/proposed auth ADRs, human backlog #79, real P4-05 account,
protected restart and service acceptance remain separate. No gate promotion.
