## What is tested

The required Windows job now compiles the probe and runs its synthetic creation,
close-event, replacement-isolation and teardown sequence three times. It rejects
unsupported/missing arguments with exact exit code 2 before native work. Native
API failures and timeouts fail CI. No frame acquisition or target enumeration is
present. Fixed test messages contain no window titles/handles or exception text.

Native compilation/execution cannot run in this Linux workspace, which has no
MSVC/Windows SDK. No local native pass or test-first failure is claimed. Windows
CI outcomes, exact head, toolchain and review follow-up are recorded in the issue
and PR. TypeScript coverage does not measure C++ coverage. Formatting checks do
not format C++/batch files; those receive direct review and compiler diagnostics.

## Security/license review and limits

Source review confirms test-owned windows only, immutable source command line,
no frame/session creation, no arbitrary target, no image/log persistence, no
network, no privilege elevation and no production import. The build script
uses installed tools, outputs under ignored dist, and uploads no executable.
The new native build inputs are inventoried in ADR 0018; no distribution clearance
is inferred from npm notices. No sample code or Microsoft artwork was copied.

Automated Server CI is not physical Windows 11 evidence. This test does not force
HWND reuse, prove external-window binding or collect pixels. OD-02 and G3 remain
open. After this PR merges and main passes, the next bounded task is an owned-window
single-frame acquisition/cleanup probe with its own privacy review. Main/helper
IPC, actual user-target selection, consent and provider transmission remain later.

## Native failure diagnosis and correction

The first candidate compiled on Windows but failed at runtime. A diagnostic rerun
identified `CreateForWindow` returning `E_INVALIDARG` (`80070057`). Fixed stage
labels and numeric HRESULT codes were added without exception text or private
metadata. The fixture now uses an ordinary application window and completes its
initial paint/compositor flush before binding. Run 38254101071 passed the native
step with this setup. This establishes that the revised fixture works; it does
not isolate whether the original style or presentation timing caused rejection.
The original failing assertion was retained; no test was skipped.

MSVC 14.51.36231 and SDK 10.0.26100.0 were observed and are now both checked
exactly. A direct follow-up review moved presentation after window construction,
so failed presentation also invokes window cleanup. Final-head Windows results
and exact-head review are recorded in the PR/issue. These corrections change
only the synthetic fixture and build diagnostics, not application capture policy.
