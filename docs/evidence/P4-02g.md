## Scope and behavioral evidence

The listener binds a random IPv4 loopback port and accepts a single state-bound
callback. The fixed-URL launcher validates the transaction's authorization shape
and arms that listener before invoking its injected opener. They are separate
main-only capabilities, not wired into the application. The transaction still
validates callback fields and controls identity and credential publication.

Initial typed stubs produced **3 failing / 1 passing** behavioral tests; the
implementation passes those cases. Two further regression tests failed when a
delayed lifetime timer allowed arming or callback delivery after the monotonic
deadline; startup, arming and handling now check the deadline independently.
The expanded tests exercise malformed and
duplicate host headers, bad paths/methods/state, bodies, request bounds,
unarmed/aborted attempts, native startup/socket errors, close/timeout races,
fixed non-reflecting responses, strict authorization URL fields, invalid opener
results, delayed completion and one-use behavior. Tests compose actual loopback
sockets with the existing transaction and synthetic browser/provider/storage
hooks, including a callback arriving before the fake opener resolves. A wrong
state does not trigger exchange; a state-matching malformed callback is rejected
by the transaction. No real token, account or provider request is used.
