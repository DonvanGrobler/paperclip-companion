## Implementation and verification

The policy validates a 2,000-character prompt plus explicit control booleans, gives
hard exclusion/Never precedence over Include, rejects idle submissions, and returns
only intent plus a fixed non-sensitive reason. Positive intent does not authorize
capture. Unknown/negated/quoted/instructional language remains text-only. The module
has no runtime caller, I/O, timer, credential, target or image access.

Corpus partitions and labels were committed locally before policy implementation,
with six label clarifications made before any classifier existed.
The final corpus hash is pinned in the metric report and regression tests. Missing
policy tests failed before implementation. The first standalone evaluation exposed
Node strip-only incompatibility with the provider's parameter-property syntax;
moving the shared constant to an erasable constants module fixed that tooling issue
without changing the provider contract or introducing dependencies.

The report [P3-04-metrics.json](P3-04-metrics.json) is reproduced by
`npm run evaluate:intent`, which also runs during `npm run check` on Windows/Ubuntu.
Tests cover all 180 negative prompts, control precedence for all 240 prompts with
both Include states, malformed/boundary/Unicode inputs, precision/recall denominators
and recorded-baseline drift. Reports/test names use IDs rather than prompt text.
All fixture text is synthetic and independently project-authored.

Direct review additionally hardened unknown-input validation: accessors are rejected
without invoking getters, non-plain prototypes are rejected, and reflection failures
return a fixed invalid-input result. No language rule/label or corpus prediction changed.

Local `npm run check` passed 632 unit tests, format/lint/strict types, the evaluation,
all builds and the unchanged 184-package license inventory. New intent policy coverage
is 100% across lines/statements/branches/functions; aggregate main/core/provider
coverage remains above the unchanged 90% thresholds (exact final figures in the PR).
`npm audit --audit-level=high` found zero vulnerabilities. No threshold was reduced.

The four missed IDs in each partition are clear-27 through clear-30. They cover
unrecognized explicit visual-reference phrasing and a legitimate request containing

This is a same-author curated split with related phrasings, not independent blinded
validation; do not generalize its precision to arbitrary users or adversaries.

**Recall target 90% is not met.** The plan expressly permits retaining fail-closed
behavior and documenting misses. That is the chosen exploratory result, not a lowered
quality gate or approval to enable capture. Any future tuning requires a new unseen
evaluation partition, with this one retained as regression material.

## Security, privacy, licensing and human evidence

Direct review: no data path to logs, disk, network, renderer IPC or capture was added.
Classifier output cannot carry private text and must never serve as capture permission.
Inputs are ordinary request records, not executable instructions. Lexical guards are
not a complete injection defense or sensitive-app policy. See [ADR 0014](../adr/0014-screen-intent-policy.md).
No dependency, lockfile, asset, source-license or permission change. The text budget
remains identical for providers and intent. Existing application entrypoints stay
unchanged; native Windows regression CI remains required for the candidate.

No new manual tests performed or requested. Exact final-head local/Windows checks,
audit and review disposition are recorded in issue #38 and its PR. Local native
Electron E2E is unavailable (no display/Xvfb); CI results are not human Windows evidence.

G1 physical display/focus/tray evidence remains open. P2 technical criteria are
verified after PR #37, but G2 promotion still waits for G1. G3 is open, including
the recall shortfall, independent evaluation and all live consent/target/capture
requirements. Next smallest task is a pure consent/request-authorization contract
and disclosure design, not switching on screenshots or real-provider egress.
