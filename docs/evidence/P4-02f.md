## Scope and behavioral evidence

The new isolated main-only HTTPS POST capability validates/copies the six-field
request, sends only the fixed code-exchange form, bounds transport/time/response
data and returns a six-field frozen projection. It does not establish identity or
session authority. Existing transaction logic now anchors token expiry before
exchange, with an active-attempt monotonic guard and post-await checks. No app
entry/preload/renderer, IPC, provider wiring, dependency/lock/inventory,
workflow or credential-schema change.

- Initial typed adapter stub: **2 failed / 1 passed** behaviorally. Minimal native
  implementation passed those initial cases and strict types.
- Reflective parsing hardening: **2 failed / 3 passed** when prototype-polluted
  fields were wrongly read from JSON object inheritance; own-field projection
  fixes both. Values in the fixtures are ephemeral synthetic markers.
- Native cleanup hardening: **2 failed / 99 passed** when simulated cleanup
  exceptions left promises unsettled. Suppressed owned-stream cleanup errors
  restore a fixed terminal outcome. A further cancellation-during-cleanup case
  failed before the post-cleanup abort recheck and now passes.
- Response ambiguity hardening: **3 failed / 107 passed** when repeated top-level
  JSON names, including Unicode-escaped spellings, were accepted. The bounded
  prepass now rejects duplicates without interpreting nested extension data.
- Deadline hardening: two cases failed before a monotonic deadline was checked;
  one initially reached the normal five-second test timeout because the unfixed
  native setup hung. Its fixture now asserts no body is sent and cleans up by
  aborting; no production or test timeout was increased or assertion weakened.
- Protocol compatibility: **4 failed / 114 passed** when valid OAuth bearer
  type spellings used different case. The adapter now canonicalizes only the
  case-insensitive bearer type; unrecognized types still fail transaction checks.
- Initial automated review 5765548747 reported it could not complete at its
  selected service tier and flagged duplicated deadline literals. The timeout
  now has a single source of truth; an independent direct source/privacy review
  supplements any incomplete bot review. No behavior or deadline changed.
- Expiry hardening: **3 failed / 199 passed** on delayed/expired/clock-rollback
  exchange results. Conservative pre-exchange expiry plus monotonic checks fixes
  those cases; additional rollback cases cover verification and preparation.
- The first full run stopped at lint on an unused synthetic fixture binding;
  the fixture was simplified and the unchanged lint policy rerun. No check or
  assertion was weakened.
- Expanded tests exercise fixed destination/method/form/TLS options; escaping,
  bounds, malformed headers/status/JSON/UTF-8, unknown provider fields, inherited
  and reflective inputs, native exceptions, late callbacks, cancellation and
  timeout. Composition tests cover callback/retention ordering, no inferred
  scope, required identity/conditional credential commit, failed replacement and
  stale-result cancellation. No token/code/verifier is logged or snapshotted.

The transport tests mock `https.request` and use synthetic Node event/byte
streams. They validate requested TLS options and cleanup, **not an actual TLS
handshake or OpenAI service behavior**. Identity/browser/credential hooks in
composition are explicit fakes. They cannot establish real issuer provenance,
real encrypted storage or account permission. No real provider request occurs.
