## Scope and test-first work

One new main-only metadata store, one required transaction retention capability,
and explicit pending-registration/returning-hint contexts. Three existing auth
composition test files add explicit retention fakes. One Node-only child fixture
checks a separate-process restart with nonsecret synthetic IDs and boolean-only
output. No app entry/preload/renderer, IPC, capture, provider, dependency, lock,
inventory, workflow or encrypted credential schema changes.

- The initial typed metadata no-op failed **3 behavioral cases**, with 4 denial
  cases already passing. Implementation then passed those initial cases.
- Added transaction tests require retention before exchange, pending retry,
  bound hint and rejection of a missing retention capability.
- Existing regression tests caught **3 reentry failures** when the initial
  parser tried two reflective shapes. A single inspection with an optional
  registration field restores the original cancellation/reentry contract.
  All initial **175 cases** then passed with strict types.
- Expanded coverage tests real temporary-directory IO, first-create collision,
  bounded reads/schema, 32-entry capacity, stable slot/host restoration, staged
  write/flush/link/rename failures, private exception handling, external changes,
  exclusive ownership/cleanup and synchronous cancellation. Composition verifies
  failed exchange retains identifiers through reopen, rejects stale proof and
  uses fresh proof with the issued client ID on a later explicit sign-in.
- Two new metadata test fixtures were corrected: an invalid-record fixture had
  accidentally become valid after adding the test host; a simulated foreign
  stage recursively invoked its own open mock. A callback assertion was corrected
  to expect rejection of stale state. No security assertion/timeout was relaxed.

The metadata tests perform actual native filesystem operations and a new Node
process, not an Electron/DPAPI or account sign-in test. Synthetic browser,
exchange, identity and credential hooks in transaction composition cannot prove
real issuer/service behavior. The hint markers are never actual user tokens;
no credential, hint, code, nonce or URL is written to metadata or child IPC.

## Security, license and remaining work

Reviewed the host/client metadata, reflective inputs, authorization hint URL,
code exchange ordering and credential paths. Only exact bounded identifiers are
plaintext; no secrets, account labels or auth/session permissions. Fixed official
authorization destination remains unchanged; hints require matching selected
identity/client and cannot bypass fresh verification. No logging, renderer
credential/URL bridge, network call, live sign-in or production capture wiring.

No new dependency or upstream code/assets: project stays UNLICENSED, inventory
unchanged. Host metadata is private but cannot establish identity or defeat
same-user tampering. Trusted private directory/ancestors and a single update
owner are prerequisites. First creation uses a native no-clobber link; unsupported
filesystems fail closed. Stale-owner detection is not multiprocess CAS. No
power-loss, secure-deletion or rollback guarantee. Cancellation after synchronous
installation may leave nonsecret registration metadata while authorizing nothing.

remain open. Prior G1–G4/OD-02 blockers remain explicit; no gate promotion and
production capture stays off. Next smallest: fixed bounded code-exchange and
